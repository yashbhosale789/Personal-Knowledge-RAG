# Contributing

## Before contributing
- Read the README and relevant architecture/security documentation.
- Check the current roadmap and open issues.
- Keep changes focused and explain the reason for the change.

## Development workflow
1. Create a focused branch.
2. Make the smallest correct change.
3. Add or update tests for changed behavior.
4. Run relevant tests, linting, and evaluation checks available in the repository.
5. Update documentation when behavior, configuration, APIs, or operations change.
6. Open a pull request describing the change, validation, risks, and any follow-up work.

## Security
Never commit credentials, private environment files, real user documents, or sensitive logs. Report suspected credential exposure without copying the credential into an issue or chat.

## Project principles
Prefer clear, maintainable, cost-conscious implementations. Do not add services or paid dependencies without documenting the trade-offs and obtaining approval where required.
