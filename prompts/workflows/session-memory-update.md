# Prompt — Session Memory Update

Review this conversation and prepare a durable update for `Memory.md`.

Capture only information useful to future project work:
1. Goal and outcome.
2. Files changed and significant implementation details.
3. Commands, tests, evaluations, and actual results.
4. Decisions, alternatives, and rationale.
5. Bugs, root causes, fixes, and lessons.
6. Verified state versus assumptions or unverified claims.
7. Open issues, risks, and next agreed action.
8. Any justified change to `Roadmap.md`.

Rules:
- Do not invent facts, files, commands, test results, or decisions.
- Do not store secrets, tokens, passwords, or private credential values.
- Avoid duplicating existing content.
- Preserve historical rationale where it matters.
- Do not mark a phase complete unless its acceptance criteria are met.
- Do not claim a file was updated unless you actually edited and verified it.

If file editing is available, inspect `Memory.md` first and merge the update into the appropriate section. Otherwise provide a ready-to-append Markdown entry and explicitly say that it has not been saved.
